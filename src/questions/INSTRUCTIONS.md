# オリジナル問題づくり

CCNA学習サイトの一般公開版のために、**著作権的に問題のない、完全オリジナルの4択問題など**を作ります。
第NN回の問題は `src/questions/lNN.json` に書きます。その回の授業のセリフと教科書は `src/lessons/lNN.json`（`cls.lines` と `pages`）にあります。

## 大事なルール
1. **完全オリジナル**：既存の問題集・Cisco試験・ネットの問題の文面、シナリオ、数値、選択肢の組み合わせをまねしない。
   「カバーしてほしい知識」は“何を確かめるか”の参考だけ。新しい場面・新しい数値・新しい言い回しで作る。
   アドレスは 192.0.2.0/24、198.51.100.0/24、203.0.113.0/24、10.x.x.x、172.16〜31.x.x、192.168.x.x、2001:db8::/32 などを自由に使う。機器名は R1・SW1・本社ルーター など。
2. **正確**：CCNA 200-301 の範囲で事実として正しいこと。正解は1つに決まり（multiは指定数ぴったり）、ほかの選択肢ははっきり間違い。
3. **この回の教科書とセリフ（と前の回で習うこと）の知識で解ける**こと。
4. その回の内容をできるだけ広くカバーし、すでにある問題と似た問題は作らない。
5. 日本語は自然に、初心者にも読める文で。略語は初出で正式名を（ ）で添える。
6. 解説（e）には「選択肢」「ひっかけ」「試験では」という言葉を使わない。

## 形式（JSONの1問の形）
共通：
- "id": 新しく作る問題は "N{回2桁}-{連番2桁}"（例 "N18-01"）。"P…" は旧50回のときに作った問題のIDで、番号は今の回と一致しない（進捗がIDで保存されているので、既存のIDは変えない）
- "k": "one"（4択1つ）/ "multi"（5択から2つ。t の最後に「2つ選んでください。」）/ "sel"（分類）/ "match"（組み合わせ）/ "order"（並べ替え）
- "tag": 次から1つ：TCP/UDP, IPアドレス, サブネット, IPv6, ケーブル, スイッチング, VLAN, STP, 無線, 仮想化, WAN, ルーティング, OSPF, 冗長化, NAT, DHCP, 管理, プロトコル, QoS, セキュリティ, ACL, SDN, REST API, AI/自動化, 設計, トラブルシュート
- "t": 問題文（HTMLは <b> と <br> のみ可）
- "e": 解説 1〜3文（なぜ正解か。<b>で要点）
- "m": 覚え方 15〜30字
- "page": この問題に一番関係する教科書ページ番号（src/lessons/lNN.json の pages の0始まりの番号。「小テスト」のページ以外）
形式ごと：
- one：  "o": [4つの文字列], "a": 正解の番号(0始まり)
- multi："o": [5つ], "a": [正解の番号2つ]
- sel：  "rows": [{"l":"項目","a":"分類名"} ×4〜6], "opts": ["分類名A","分類名B",...]
- match："o": [["左","右"] ×4]（正しい組み合わせで書く。表示時にシャッフルされる）
- order："o": [正しい順に4〜5個]
構成図（機器のつながり）は、文字の図ではなく `tools/qfigs.py` の FIG に絵（SVG）で描く（build で問題に入る。答えになる情報は図に書かない）。
図・出力付きにする場合（show コマンドの出力・設定・WLC画面・JSONなど。オリジナルで作る）：
- "x": テキストの図（改行は \n、20行以内、1行60字以内、半角スペースで位置をそろえる）
- "rd": 図・出力の読み方を「①…<br>②…<br>③…」の形で（見る行・比べる所・結論）。e と同じ内容をくり返さない
- "rg": 読み方ガイドの種類を1つ：topo, route, intf, brief, run, vlan, stp, ospf, acl, nat, sw, wlc, data, pc, log
- t は「図を参照してください。」で始める
難易度（"lv"、全問に付ける）：
- "lv": 1 … **基礎**。用語・数字・コマンドの意味を1つ知っていれば解ける。
- "lv": 2 … **本番レベル**。模擬試験はここから出す。次のうち2つ以上を満たすこと。
  1. 図・出力（x）や、具体的な機器・アドレス・設定のある場面を読ませる
  2. 2段階以上考えないと解けない（例：ルート表を読む → 一番長い一致 → AD を比べる）
  3. 間違いの選択肢も「それらしい」（コマンドの細部・数値の境目・よく似た用語）。明らかな間違いを入れない
  4. 2つ以上の回・単元の知識を組み合わせる
- 本番レベルの**問題文**は本番に近い言い回しにしてよい（「〜はどれですか。」「最も適切なものはどれですか。」、機器名・設定・出力をそのまま示す）。**解説（e）と覚え方（m）は、これまでどおりやさしい日本語**で書く。
- 第1〜8回（ゼロからの入門）は試験範囲の前提なので、すべて lv 1。
- 本物の試験問題（いわゆる過去問・ダンプ）は使わない。形式と難しさだけを本番に合わせ、場面・数値・言い回しはオリジナルにする。
形式の割合の目安：one 約75%、multi 約10%、sel/match/order 合わせて約15%。図・出力付きは指定の目安数。

## 反映と確認
`src/questions/lNN.json`（問題の配列）を書いたら `python tools/build.py` を実行する。
data.json が作り直され、続けて check.py が ID の重複・a の範囲・page の範囲などを点検する。「問題なし」になるまで直す。
